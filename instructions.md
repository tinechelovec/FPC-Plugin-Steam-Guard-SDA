# 🔐 Steam Guard (SDA) — инструкция по установке и настройке

Привет! Это альтернативная инструкция для **Steam Guard (SDA)** — плагина для FunPay Cardinal, который автоматически генерирует и отправляет Steam Guard-коды покупателям по заданным командам.

Плагин работает с `shared_secret` от Steam Desktop Authenticator и умеет автоматически получать необходимые данные из `.maFile`.

> Основная инструкция: https://teletype.media/@tinechelovec/Steam-Guard-SDA
> GitHub: https://github.com/tinechelovec/FPC-Plugin-Steam-Guard-SDA

---

# 📌 Что делает плагин

Steam Guard (SDA) умеет:

* добавлять несколько Steam-аккаунтов;
* импортировать аккаунт из `.maFile`;
* принимать `shared_secret` вручную;
* автоматически генерировать Steam Guard-коды;
* создавать отдельную команду для каждого аккаунта;
* автоматически предлагать команду по названию аккаунта;
* использовать собственную команду;
* устанавливать лимит выдачи кодов;
* устанавливать период сброса лимита;
* работать без лимитов;
* использовать очередь запросов;
* отдельно включать очередь для каждого аккаунта;
* отдельно включать или выключать выдачу для каждого аккаунта;
* отправлять уведомления о командах;
* использовать общий текст ответа;
* использовать отдельный текст для каждого аккаунта;
* вести логи;
* использовать чёрный список покупателей;
* применять чёрный список ко всем или только выбранным аккаунтам;
* экспортировать конфигурацию;
* импортировать конфигурацию;
* обновлять плагин через Telegram.

Steam Guard-коды генерируются самим плагином из `shared_secret`.

---

# ⚠️ Важно про shared_secret и maFile

`shared_secret` — это чувствительные данные Steam Guard.

Человек, у которого есть ваш `shared_secret`, может генерировать Steam Guard-коды для соответствующего аккаунта.

Поэтому:

> **Никому не отправляйте свой `shared_secret` или `.maFile`.**

Также не загружайте их на неизвестные сайты и не публикуйте в открытом доступе.

Конфигурация Steam Guard (SDA) тоже может содержать `shared_secret`, поэтому относитесь к экспортированному конфигу как к приватному файлу.

# 🚀 Установка плагина

Для работы нужен установленный **FunPay Cardinal**.

После установки Cardinal:

1. скачайте актуальный `.py`-файл Steam Guard (SDA);
2. откройте Telegram-бота Cardinal;
3. отправьте:

```text
/menu
```

4. перейдите во вкладку **«Плагины»**;
5. загрузите файл Steam Guard (SDA);
6. откройте установленный плагин.

Меню SDA также можно открыть командой:

```text
/sda_menu
```

# 🔌 Включение и выключение плагина

Кнопка:

**🔌 Плагин: ВКЛ / ВЫКЛ**

полностью управляет обработкой команд.

Если плагин выключен, команды покупателей не будут приводить к выдаче Steam Guard-кодов.

Настройки и добавленные аккаунты при этом не удаляются.

---

# ➕ Добавление Steam-аккаунта

Нажмите:

**➕ Добавить аккаунт**

Плагин предложит добавить данные Steam Guard.

Есть два варианта:

1. отправить `shared_secret` вручную;
2. отправить `.maFile`.

---

# 🔐 Вариант 1 — shared_secret

Если у вас уже есть `shared_secret`, просто отправьте его текстом.

Плагин сразу проверяет, можно ли с его помощью сгенерировать Steam Guard-код.

Если secret некорректный, аккаунт не будет добавлен.

После успешной проверки нужно указать название аккаунта.

Например:

```text
tinechelovec
```

После этого плагин предложит команду примерно такого вида:

```text
!code_tinechelovec
```

---

# 📁 Вариант 2 — maFile

Если вы используете Steam Desktop Authenticator, можно просто отправить файл:

```text
account.maFile
```

Плагин самостоятельно попытается найти внутри:

```text
shared_secret
```

и название аккаунта.

То есть вручную копировать secret из JSON необязательно.

Поддерживается обычный `.maFile`, внутри которого доступен `shared_secret`.

Максимальный размер файла для загрузки в плагин — **2 МБ**.

---

# 📂 Где находится maFile

В Steam Desktop Authenticator файлы аккаунтов обычно находятся в папке:

```text
maFiles
```

Внутри находятся файлы примерно такого вида:

```text
1234567890.maFile
```

или с другим названием в зависимости от версии SDA.

Именно этот `.maFile` можно отправить плагину.

> ⚠️ Не отправляйте `.maFile` другим людям.
>
> Этот файл содержит данные Steam Guard.

# 💬 Команда аккаунта

После получения secret плагин предложит команду автоматически.

Например, для аккаунта:

```text
MySteam
```

может быть предложена команда:

```text
!code_mysteam
```

Есть два варианта.

## ✅ Использовать предложенную

Просто нажмите кнопку с готовой командой.

## ✏️ Создать свою команду

Можно указать собственную команду.

Например:

```text
!steam
```

или:

```text
!code_main
```

Каждая команда должна быть уникальной.

Нельзя назначить одну команду двум разным SDA-аккаунтам.

Команда:

```text
/sda_menu
```

зарезервирована самим плагином и не может использоваться для выдачи кодов.

# 🛒 Как покупатель получает код

Допустим, для Steam-аккаунта настроена команда:

```text
!code_main
```

Покупатель пишет её в чате FunPay:

```text
!code_main
```

После этого Steam Guard (SDA):

1. находит аккаунт, которому принадлежит команда;
2. проверяет, включён ли плагин;
3. проверяет, включена ли выдача для аккаунта;
4. проверяет чёрный список;
5. проверяет лимит покупателя;
6. учитывает настройки очереди;
7. генерирует Steam Guard-код;
8. отправляет покупателю настроенное сообщение;
9. записывает выдачу в статистику и логи.

---

# 🔢 Лимиты

Для каждого Steam-аккаунта можно установить отдельный лимит.

Например:

```text
5
```

После этого плагин спросит период лимита.

---

# ⏱ Лимит за определённое время

Например:

```text
5
```

кодов за:

```text
24
```

часа.

Это означает:

> Один покупатель может получить максимум **5 кодов за 24 часа** по этой команде.

Когда 24 часа пройдут, его счётчик сбросится.

---

# ♾ Лимит навсегда

Если после количества кодов указать:

```text
0
```

или:

```text
-
```

в поле периода, лимит не будет автоматически сбрасываться.

Например:

```text
3 навсегда
```

означает, что конкретный покупатель сможет получить только 3 кода по этой команде.

---

# 🚫 Без ограничений

Если на этапе количества отправить:

```text
-
```

лимит полностью отключается.

Покупатель сможет запрашивать коды без ограничения по количеству.

---

# ⏳ Очередь

Steam Guard-код зависит от текущего временного окна.

Один код действует в пределах примерно **30 секунд**.

Если несколько покупателей одновременно попросят код от одного и того же Steam-аккаунта, выдавать всем один и тот же текущий код нежелательно.

Для этого в плагине есть очередь.

---

# 🌐 Общая очередь

В главных настройках есть:

**⏳ Очередь: ВКЛ / ВЫКЛ**

Это глобальный переключатель.

Если общая очередь выключена, индивидуальная очередь аккаунта фактически тоже не работает.

---

# 👤 Очередь отдельного аккаунта

У каждого аккаунта есть собственная настройка:

**⏳ Очередь аккаунта: ВКЛ / ВЫКЛ**

Очередь работает только если одновременно:

* плагин включён;
* общая очередь включена;
* аккаунт включён;
* очередь конкретного аккаунта включена.

---

# 🔄 Как работает очередь

Представим, что покупатель A запросил код.

Плагин выдаёт ему текущий Steam Guard-код и закрепляет текущее временное окно.

Если в этот же момент покупатель B запросит код от того же аккаунта, он становится в очередь.

Следующий код выдаётся уже в следующем временном окне.

Примерно:

```text
Покупатель A → текущий код
Покупатель B → следующий код через ~30 секунд
Покупатель C → ещё следующий код
```

Плагин показывает покупателю его позицию и примерное время ожидания.

---

# 🔁 Повторный запрос того же покупателя

Если покупатель уже получил код в текущем временном окне и снова отправляет команду, при включённой очереди он может быть поставлен на получение следующего кода.

Если он уже находится в очереди, повторно создавать ещё одну одинаковую позицию плагин не должен.

---

# ⚡ Выдача кодов аккаунта

У каждого добавленного аккаунта есть собственный переключатель:

**⚡ Выдача кодов: ВКЛ / ВЫКЛ**

Это позволяет временно отключить конкретный Steam-аккаунт, не выключая весь плагин.

Например:

```text
Steam Main — ВКЛ
Steam Second — ВЫКЛ
Steam Test — ВКЛ
```

Тогда команды Main и Test работают, а Second временно не выдаёт коды.

---

# 🔔 Уведомления команд

Есть глобальная настройка:

**🔔 Уведомления команд**

а также отдельная настройка у каждого аккаунта.

Это позволяет управлять служебными уведомлениями, связанными с использованием команд.

Уведомления конкретного аккаунта фактически работают только тогда, когда включены:

* глобальные уведомления;
* уведомления самого аккаунта;
* сам аккаунт и плагин находятся в рабочем состоянии.

---

# 🚫 Чёрный список

В Steam Guard (SDA) есть встроенный чёрный список покупателей.

Он позволяет запретить определённым никам получать коды.

В меню отображается:

* состояние ЧС;
* область применения;
* количество ников;
* количество выбранных аккаунтов;
* текст ответа заблокированному пользователю.

---

# 👤 Добавление ника в чёрный список

Откройте:

**🚫 Чёрный список → 👤 Ники → ➕ Добавить ник**

Отправьте один ник.

Можно написать:

```text
badbuyer
```

или:

```text
@badbuyer
```

Плагин нормализует ник и сохранит его в списке.

После добавления первого ника чёрный список автоматически включается.

---

# ❌ Удаление из чёрного списка

В списке ников каждый пользователь отображается отдельной кнопкой.

Нажмите на нужный ник, чтобы удалить его из ЧС.

---

# 🎯 Где действует чёрный список

Есть два режима.

## Все аккаунты

Заблокированный покупатель не может получать коды ни от одного SDA-аккаунта.

## Выбранные аккаунты

Чёрный список работает только для Steam-аккаунтов, которые вы отметили вручную.

Например:

```text
✅ Steam Main
⬜ Steam Second
✅ Steam Test
```

В этом случае заблокированный покупатель не получит код от Main и Test, но правило ЧС не будет применяться к Second.

---

# 💬 Сообщение чёрного списка

Можно изменить сообщение, которое получает заблокированный покупатель.

По умолчанию используется примерно:

```text
⛔ Вы находитесь в чёрном списке.
Выдача Steam Guard кода для аккаунта «{name}» недоступна.
```

---

# 🧩 Переменные сообщения ЧС

# 📤 Экспорт конфигурации

Плагин создаёт JSON-файл с:

* общими настройками;
* добавленными аккаунтами;
* командами;

> ⚠️ Экспортированный конфиг содержит `shared_secret`.

# 📥 Импорт конфигурации

Можно загрузить ранее сохранённый JSON-конфиг.

Плагин проверяет:

* структуру файла;
* количество аккаунтов;
* команды;
* дубликаты команд;
* наличие `shared_secret`;
* корректность secret;
* лимиты;
* остальные параметры.

После успешного импорта текущая конфигурация заменяется импортированной.

Перед импортом рекомендуется сохранить текущий конфиг.

---

# 🔄 Как генерируется Steam Guard-код

Steam Guard использует временные коды.

Плагин берёт:

```text
shared_secret
```

и текущее время сервера, после чего локально вычисляет пятисимвольный Steam Guard-код.

Код меняется примерно каждые:

```text
30 секунд
```

Поэтому очередь также ориентируется на 30-секундные временные окна.

---

# 🗂 Какие данные хранит плагин

Steam Guard (SDA) хранит локально:

* настройки;
* Steam-аккаунты;
* `shared_secret`;
* лимиты;
* статистику использования;
* очередь;
* логи.

Основные файлы находятся в папке плагина Cardinal.

Из-за наличия `shared_secret` не передавайте папку данных плагина посторонним.

# ⬆️ Обновление плагина

В главном меню есть:

**⬆️ Обновить плагин**

Поддерживаются два способа.

---

# 📥 Локальное обновление

Можно отправить новый `.py`-файл Steam Guard (SDA).

Перед установкой плагин проверяет:

* что это Python-файл;
* что внутри действительно Steam Guard (SDA);
* UUID;
* VERSION;
* синтаксис Python.

Текущий файл сохраняется в резервную копию.

Данные и настройки остаются на месте.

---

# 🌐 Онлайн-обновление

Плагин может проверить официальный файл на GitHub.

Сравнивается не только номер версии, но и содержимое файла.

Поэтому обновление может быть предложено даже при одинаковом номере версии, если содержимое файла изменилось.

---

# 🗑 Удаление плагина

В главном меню есть:

**🗑 Удалить**

Перед удалением появляется подтверждение.

При полном удалении могут быть удалены:

* файл плагина;
* аккаунты;
* настройки;
* очередь;
* статистика;
* логи.

После удаления выполните:

```text
/restart
```

Если данные могут понадобиться позже, **сначала скачайте конфиг**.

---

# ❓ Если команда не работает

Проверьте:

1. включён ли сам плагин;
2. включена ли выдача у нужного аккаунта;
3. правильно ли написана команда;
4. не была ли команда изменена;
5. не находится ли покупатель в чёрном списке;
6. не исчерпан ли лимит;
7. корректный ли `shared_secret`;
8. что написано в логах.

---

# ❓ Если покупатель получает сообщение о лимите

Проверьте настройки конкретного аккаунта.

Например:

```text
5 за 24ч
```

означает, что один покупатель может получить максимум 5 кодов за 24 часа.

После исчерпания лимита плагин сообщит, сколько осталось до следующего сброса.

Если лимиты вам не нужны, установите:

```text
-
```

---

# ❓ Если покупатель стоит в очереди

Это нормальное поведение при включённой очереди.

Следующий Steam Guard-код появляется в новом временном окне примерно каждые 30 секунд.

Если перед покупателем уже есть другие запросы, ожидание будет увеличиваться.

---

# ❓ Если очередь не нужна

Есть два варианта.

Можно полностью отключить:

**⏳ Очередь**

в глобальных настройках.

Или оставить общую очередь включённой, но выключить её только для конкретного SDA-аккаунта.

---

# ❓ Если maFile не принимается

Проверьте:

1. расширение файла должно быть `.maFile`;
2. файл должен содержать корректный JSON;
3. внутри должен присутствовать `shared_secret`;
4. `shared_secret` должен быть рабочим;
5. размер файла должен быть не больше 2 МБ.

Если maFile не подходит, можно добавить `shared_secret` вручную.

---

# ❓ Если код Steam Guard неправильный

Проверьте:

1. правильный ли `shared_secret` установлен для аккаунта;
2. не перепутали ли вы `.maFile` от разных Steam-аккаунтов;
3. не был ли Steam Guard перепривязан после сохранения secret;
4. актуальные ли данные находятся в плагине.

Если secret изменился, откройте аккаунт и используйте:

**🔐 Заменить secret / maFile**

---

# ✅ Рекомендуемая первая настройка

Если устанавливаете Steam Guard (SDA) впервые:

1. установите плагин;
2. прочитайте инструкцию;
3. добавьте **один** Steam-аккаунт;
4. лучше загрузите его `.maFile`;
5. оставьте автоматически предложенную команду;
6. установите небольшой тестовый лимит;
7. оставьте очередь включённой;
8. оставьте стандартный текст ответа;
9. протестируйте команду в FunPay;
10. убедитесь, что код генерируется правильно;
11. только потом добавляйте остальные аккаунты.

Так намного проще найти ошибку, если что-то настроено неправильно.
